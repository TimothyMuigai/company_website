## What we're building

A full event/training booking system on your site:

1. **Public `/events` page** — lists upcoming trainings with date, location, price (or "Free"), seats left, and a Book button.
2. **Event detail page** — full description, agenda, facilitator, price, book/checkout.
3. **Booking flow** — collects attendee name, email, company, phone. Free events reserve immediately; paid events go through checkout.
4. **Confirmation page** — shows booking reference + 3 "Add to Calendar" buttons: **Google Calendar**, **Outlook / Microsoft Teams**, and **Apple / iCal (.ics download)**.
5. **Confirmation email** — sent automatically with an `.ics` attachment (opens natively in Apple Mail, Outlook, Gmail → adds to their calendar in one click) plus the same 3 web buttons.
6. **Admin dashboard at `/admin`** — protected page where you sign in, create/edit/delete events (title, description, date, duration, location, price, capacity, meeting link for virtual events), and see the list of bookings per event with export.
7. **Seed data** — 3 realistic upcoming trainings pre-populated so the page isn't empty on launch.

## Calendar integration — how it works

- **Google Calendar button** → opens a pre-filled Google Calendar event in a new tab. The attendee clicks Save.
- **Outlook / Teams button** → opens Outlook Web's "add event" URL. Meetings added to Outlook automatically appear in Teams calendar for the same account. (True Teams meeting *creation* — with a join link generated by Teams — requires connecting your company's Microsoft 365 account, which is a separate integration. I'll flag it as a follow-up if you want that.)
- **Apple / iCal button** → downloads a standards-compliant `.ics` file that works with Apple Calendar, Outlook desktop, Thunderbird, and any calendar app.
- **Email `.ics` attachment** → most email clients render this as a one-click "Add to Calendar" prompt.

## Technical notes

- Events table + bookings table in the database, with row-level security so only admins edit events and see all bookings; attendees only see their own booking.
- Admin role stored in a separate `user_roles` table (not on the profile) — standard secure pattern.
- `.ics` files generated server-side from event data (title, description, location, start/end in UTC).
- Paddle checkout runs in an overlay on the event page; webhook confirms payment before the booking is marked `paid` and the confirmation email fires.
- Admin dashboard: create/edit event form, bookings list per event, CSV export.
